## Safety reason

Targeted read @56aa319, not full engine/dependency/binary audit. CAUTION: early alpha with host process/file/network authority. Clean room defaults to visible behavior and limits offered analysis tools (README.md:129-143), but explicitly is NOT an OS sandbox or legal guarantee. Critical default: auto_mode=true (crates/engine/src/settings.rs:107-111,207); ActionKind::Commands Auto policy is Allow (workspace.rs:1107; docs/claude-code.md:25-37). Builds can automatically run known install/build commands and edit project app files. Switch Auto mode OFF and review per-project approvals; do not leave commands, outside files, publishing/push/delete/system changes broadly allowed. Arbitrary allowed shell commands can defeat app-level restrictions. Other-agent enforcement is uneven; docs/claude-code.md:57-61 notes chat restrictions not imposed on several adapters and live verification gaps. Antigravity builder adapter specifically adds --dangerously-skip-permissions (cli_agents/adapters/antigravity.rs:4,18); this is not a claim Claude Code defaults to that flag. Do not use that adapter for a first trial. Claude integration runs your installed unmodified claude headlessly with stream-json/resume and supplies a strict MCP config plus custom permission-prompt tool (docs/claude-code.md:8-39; crates/ai/src/cli_agents/adapters.rs:432-438). It does not require giving this app Claude account tokens; sign-in stays with the CLI. PostToolUse command hook runs its builder-notes CLI after tool calls (adapters.rs:320-326; :436 passes settings). This is genuine hook execution, not merely React-style hooks. craft-anything-cli setup modifies/registers MCP client configuration and installs a skill (crates/setup/src/lib.rs:1-3 and README.md:180-182): inspect the plan and obtain approval before applying. Host inherited environment/files remain part of the attack surface; untrusted targets/evidence can prompt-inject the builder. No blanket MCP or shell permission grant. Credentials/storage: API-key mode and optional generated assets DO handle keys separately from Claude CLI sign-in. crates/ai/src/keys.rs:74-77,126-143 prefers OS keychain, then falls back to readable TOML config/ai-keys.toml; this fallback is NOT encrypted. platform/src/fs.rs:52-60 applies 0600 only on Unix and ignores the private flag on non-Unix creation; do not claim enforced owner-only Windows ACLs. Use OS credential storage or ephemeral environment, no production keys, verify actual Windows file permissions before any saved API-key setup. Project data remains on disk: Documents/Craft Anything by default, craft.json/history, capture/, app/, checks/, investigation.cany/, inbox/ (README.md:221-229). journal.rs:1,46-56 logs JSONL and redacts a named secret-field list, not arbitrary secrets in source/screenshots/prose. No all-data encryption or retention guarantee reviewed. Network/telemetry/updates: target-site/browser study makes requests; hosted AI/asset providers receive inputs/prompts when configured (AI HTTP JSON POST in crates/ai/src/http.rs:144; README.md:155-167,237-243). fal.ai assets opt-in and billed separately. MCP plugins and game engines can launch external processes/tools; review each before enabling. No telemetry SDK or automatic Windows software updater found in targeted first-party runtime scan; Sentry/PostHog strings in crates/js/src/vendor.rs:73-74 identify libraries in analyzed targets, NOT evidence the app reports telemetry. Demo update URLs in ui-egui/src/demo.rs are examples, not real app update endpoints. Official ArtCraft Launcher can manage updates separately; standalone releases are smaller initial scope. README documents AppImageUpdate for Linux, not a Windows auto-updater. No first-party curl|bash installer found in targeted install docs. Setup/build/engine provisioning and dependencies still contact registries/download hosts; not offline by default, not a full dependency/binary audit. No fix: Clean room is not an OS sandbox (README.md:129-143) and allowed shell commands run with your rights; contained by Auto off, Ask on commands and a disposable project.

## Safe install

Safe install (fixes applied):
Windows: download the standalone x64/ARM64 MSI or portable build from https://getartcraft.com/apps/craft-anything or GitHub Releases (README.md:267-279) and check its signature/checksum first. Before the first build: switch Auto mode OFF (on by default, crates/engine/src/settings.rs:107-111), keep Clean room ON, and set Commands, outside files, publish/push/delete and system changes to Ask in per-project approvals (Commands default Allow, workspace.rs:1107). Use the Claude Code builder only, never the Antigravity adapter (adds --dangerously-skip-permissions, cli_agents/adapters/antigravity.rs:4,18). Don't save API keys in the app: on Windows the fallback is plain ai-keys.toml without owner-only rights (keys.rs:126-143, platform/src/fs.rs:52-60); stay on Claude CLI sign-in and leave fal.ai off. Read the `craft-anything-cli setup` plan before applying it (it edits MCP client configs and installs a skill, crates/setup/src/lib.rs:1-3). Use a disposable project with no secrets; no MCP plugins or engines. Hermes: untested. claude.ai, Android: no route.
